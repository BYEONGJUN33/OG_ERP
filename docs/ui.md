# 정보 구조

화면을 어떻게 나누고 무엇을 어디에 두는지. 시각 디자인은 여기 없다.
디자인이 바뀌어도 이 구조는 유지한다.

## 전제

- 포털이 업무의 시작점이다. 출근 → 로그인 → 여기서 모든 게 시작된다.
- **목표: Airtable UI를 켤 일이 없게 만든다.** 읽기만이 아니라 쓰기도 포털에서.
  Airtable은 뒤에서 데이터를 담는 곳이지 사람이 쓰는 화면이 아니다.
- 2명이지만 서로 뭘 하는지 보여야 한다. 다만 내 것과 남의 것이 섞이면 안 된다.

## 내비게이션 — 사이드바

상단 탭이 아니라 사이드바. ERP는 결국 메뉴가 열 개를 넘고,
상단 탭은 다섯 개에서 무너지지만 사이드바는 스무 개도 버틴다.
지금 네 개뿐이라 과해 보여도 나중에 구조를 안 바꾸는 쪽을 고른다.

```
오늘        ← 로그인 후 첫 화면
일정
할 일
프로그램
──────────
(영업)      ← 아래는 나중. 자리만 비워둔다
(구매·수입)
(재고)
(신청)
```

## 화면

### 오늘 `/`

출근해서 여는 화면. 오늘치만 모아 보여준다.

1. **내 할 일** — 마감이 오늘이거나 지난 것 + 진행중
2. **팀 할 일** — 다른 사람 담당. **내 것과 같은 목록에 섞지 않는다.**
   구획을 나누고 담당자를 제목에 둔다.
3. **오늘 일정** — 캘린더에서 오늘 것만
4. **오늘 끝낸 일** — 완료일시가 오늘인 것. 내 것과 팀 것 모두.

4번이 핵심이다. 남은 일만 보이면 "오늘 뭐 했지"에 답이 안 된다.
그리고 이걸 날짜로 필터한 것이 곧 업무일지다.

### 일정 `/calendar`

- 자체 월간 달력. 서버가 구글 API로 읽어 직접 그린다
- 출처는 여럿을 겹친다: 공용 캘린더 + 대한민국 공휴일 + 보는 사람 본인 것
- 개인 캘린더는 각자 자기 것만 보인다. 서로의 개인 일정은 보이지 않는다
- 할 일 마감이 같은 격자에 겹쳐 뜬다. 완료된 것은 제목 앞에 ✓
- 할 일을 누르면 상세 화면으로 간다(같은 탭). 구글 일정은 구글로(새 탭)
- 홈의 '오늘 일정'에는 구글 일정만 — 할 일은 바로 위 구획에 이미 있다
- 일정 등록은 구글이 한다. [일정 추가]는 구글의 등록 화면을 새 탭으로 연다.
  반복·장소·첨부·초대를 우리가 다시 만들지 않는다.
- **할 일을 캘린더에 넣는 버튼은 만들지 않는다.** 같은 일이 두 곳에 생기고
  한쪽만 고치면 어긋난다. 할 일 마감은 2단계 자체 뷰에서 겹쳐 본다.

### 할 일 상세 `/todos/[id]`

Jira 이슈 화면의 좌우 배치를 따른다. 익숙한 구조라 설명이 필요 없다.

- 왼쪽: 제목, 설명 — 내용
- 오른쪽: 상태, 담당자, 시작일, 마감일, 분류, 만든 사람 — 속성
- **상태만 즉시 저장된다.** 완료일시를 짝으로 찍어야 하기 때문이다.
  나머지는 [저장]을 눌러 한 번에 보낸다.
- 목록의 제목을 누르면 여기로 온다.

- 아래에 댓글. `할일.댓글` 한 칸에 텍스트로 쌓인다.
  "날짜 시각 이름" 다음 줄에 내용, 최신이 맨 위.

아직 없는 것: 거래처 연결, 첨부, 모달로 열기.

### 할 일 목록 `/todos` (아직 없음)

- 전체 목록. 담당자·상태·분류로 거른다
- 완료 건은 날짜로 걸러 업무일지로 쓴다
- 지금은 '오늘' 화면에서 오늘치만 본다. 전체 목록이 필요해지면 만든다

### 프로그램 `/programs`

- Airtable `프로그램` 테이블이 그대로 화면이 된다
- 카드를 누르면 도구가 열린다. **내부 도구도 새 창으로 연다**
  (도구 안에서 작업 중에 포털로 되돌아가면 작업이 날아간다)

## 규칙

- 내 것과 남의 것은 구획을 나눈다. 한 목록에 섞고 이름표만 붙이지 않는다.
- 오늘 화면은 요약이다. 전체는 각 화면에서 본다.
- 새 영역이 생기면 사이드바에 한 줄 추가. 기존 화면을 건드리지 않는다.

## 나중에 얹을 것 (지금 만들지 않는다)

이미 Airtable에 데이터가 있어서 화면만 붙이면 되는 것들.

| 영역 | 쓸 데이터 | 비고 |
|---|---|---|
| 영업 | 견적서 발송 내역, 제안 이력, 영업일지, 거래처 | 상태·납기·입금까지 이미 있음 |
| 구매·수입 | 발주서, 선적차수 | |
| 재고 | 재고 | 4군데 흩어짐 — 통합이 선행 |
| 신청 | (신청서 테이블 신설) | 연차·휴가·출장 |

견적 현황은 견적서 생성기 안에서 이미 보인다. 포털로 옮기는 건 급하지 않다.

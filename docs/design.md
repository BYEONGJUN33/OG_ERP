# 디자인 규칙

색·간격·글자를 화면마다 정하지 않는다. 여기서 정하고 화면은 따른다.
값은 `src/app/globals.css` 한 곳에 있다. 바꿀 일이 생기면 거기만 고친다.

## 태도

- 화려함보다 평범하고 직관적으로 (원칙 7)
- 업무 도구다. 하루에 수십 번 본다. **읽기 쉬운 게 예쁜 것보다 중요하다**
- 색으로 멋을 내지 않는다. 색은 **뜻이 있을 때만** 쓴다

## 형태

각지게 간다. 모서리 **3px**, 그림자는 거의 없이 선으로 구획을 나눈다.
Jira를 참고했다 — 정보가 빽빽한 업무 화면에서는 둥근 모서리와 그림자가
칸을 흐리게 만든다.

## 색

| 이름 | 쓰임 |
|---|---|
| `brand` | 기본 동작 버튼, 선택된 메뉴, 오늘 표시 |
| `ink` / `muted` / `faint` | 본문 / 보조 설명 / 더 옅은 것 |
| `line` | 테두리와 구분선 |
| `surface` / `canvas` | 카드 바탕 / 페이지 바탕 |

brand는 **초록**이다. 식물 유통 회사이고, 파랑은 어느 업무 도구에나 있어
기억에 안 남는다. 다만 넓은 면에 칠하지 않는다 — 버튼과 표시에만.

**분류는 라벨 칩으로 쓴다.** 카드 왼쪽에 색 띠를 두르지 않는다 —
색이 '분류'와 '급함' 두 가지 뜻을 동시에 지면 아무 뜻도 못 갖는다.

| 분류 | 색 |
|---|---|
| 영업 | 보라 |
| 수입 | 파랑 |
| 시공 | 청록 |
| 자재 | 주황 |
| 내부·기타 | 회색 |

| 상태 | 색 |
|---|---|
| 할 일 | 회색 |
| 진행중 | 파랑 |
| 완료 | 초록 |
| 보류 | 붉은 기 |

급한 것은 **마감일 글자 색**으로만 알린다. 지났으면 빨강, 오늘이면 굵게.

### 캘린더 색은 우리가 정하지 않는다

구글 일정은 **사용자가 구글에서 지정한 색을 그대로 읽어 쓴다**
(일정별 `colorId`, 없으면 캘린더 자체 색). 공휴일을 빨강으로, 박람회를
노랑으로 바꾸고 싶으면 구글 캘린더에서 바꾸면 포털도 따라온다.
코드를 고치거나 배포할 일이 없다.

할 일 마감은 분류 색을 쓴다.

## 글자

| 쓰임 | 크기 |
|---|---|
| 화면 제목 | 20px (`text-xl`) |
| 구획 제목 | 13px, 회색 |
| 본문 | 14px (`text-sm`) |
| 보조 | 12px (`text-xs`) |

한글 우선 시스템 폰트. 웹폰트를 받지 않는다.
16px 이상은 쓰지 않는다 — 정보 밀도가 높은 화면이라 커지면 한 눈에 안 들어온다.

## 간격

4의 배수만 쓴다. 구획 사이는 32px, 카드 안쪽은 16px, 줄 사이는 12px.

## 공통 클래스

화면에서 긴 유틸리티 나열을 반복하지 않는다. `globals.css`에 있다.

- `.btn` / `.btn-primary` — 버튼
- `.field` — 입력칸·선택상자
- `.card` — 테두리 있는 상자 (3px)
- `.section-title` — 구획 제목
- `.chip` — 분류·상태 칩 (색은 `src/lib/labels.ts`)

새 화면을 만들 때 이 클래스로 먼저 시도하고, 모자랄 때만 유틸리티를 더한다.

## 레이아웃

- 왼쪽 사이드바(200px) + 본문. 폭은 최대 1180px
- **주된 동작 버튼은 항상 화면 오른쪽 위.** 화면마다 자리가 달라지지 않게
- 정규 시간은 `src/config/workday.ts`. 주간 격자가 이걸 따른다

## 창(모달)

만들기·보기는 화면을 떠나지 않고 창으로 연다. 구조는 셋으로 고정한다.

1. **머리** — 제목 + 닫기(×)
2. **본문** — 칸을 **한 열로** 쌓는다. 칸 이름은 왼쪽 위에 작게
3. **바닥** — 구분선 위 오른쪽에 [취소] [만들기]

Esc와 바깥 클릭으로 닫힌다. 열려 있는 동안 뒤 화면은 스크롤되지 않는다.
- 사이드바는 좁은 화면에서 위쪽 가로 막대가 된다
- 한 화면에 구획을 5개 넘게 쌓지 않는다. 넘으면 화면을 나눈다
